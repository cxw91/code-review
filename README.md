# Code Review · 交互式代码审查

只读审查代码、输出结构化问题报告、附带可选修复方案，并在你指定编号后直接落地修改原始文件的安全可控代码审查技能。

## 为什么需要它

普通审查容易两极化：要么只给建议不动手，要么一把梭改乱源码。

本技能严格遵循 **只读审查 → 结构化报告 → 你勾选编号 → 直接改原文件** 的流程：

- 审查阶段（阶段 0~4）绝不修改任何文件
- 你明确告知要修复的编号（如 `C1`、`all`、`Critical`）即视为授权修改
- 修复时保持源码干净，不塞「[C1 修复]」这类注释

## 使用方法

### 触发方式

在对话中要求审查代码即可，例如：

> 审查 src/ 目录下的代码
> 帮我 review 一下 utils.py

或直接使用斜杠命令 `/code-review`。

### 执行流程

1. **审查范围核实（阶段 0）**：核对工程文件（`.uvprojx` / `Makefile` / `package.json` 等），只审查实际参与编译的代码；第三方库只记使用方式问题；目录残留但未编译的死代码不审查。
2. **只读审查（阶段 1）**：从安全性、正确性、性能、可读性、扩展性五个维度逐一检查，问题分 Critical / Major / Minor / Suggestion 四级。
3. **结构化报告（阶段 2~3）**：输出 Markdown 审查报告（含基本信息、问题列表、每项修复方案代码块），保存为 `代码审查报告.md`。
4. **勾选清单（阶段 4）**：自动生成一个可勾选的 HTML 清单，你在里面勾选项目 → 点【复制所选编号】→ 粘贴回来即可，无需手敲长串编号。
5. **执行修复（阶段 5）**：根据你回传的编号（支持 `all` / `Critical` / `C1,M5` / `show:C5` 等）用 Edit/Write 直接改原文件。
6. **修复报告（阶段 6）**：汇总改动，写出 `审查修复报告.md`，含文件列表、对应问题编号与关键 diff。

### 选择语法

| 输入 | 含义 |
|------|------|
| `all` | 修复全部问题 |
| `Critical` / `Major` | 修复该级别全部 |
| `C1, M2, m3` | 仅修复指定编号 |
| `show: C5` | 只看方案、不碰原文件 |
| `none` | 结束，不修复 |

## 目录结构

```
code-review/
├── SKILL.md   # 技能定义与完整审查规则
└── README.md  # 本说明
```

## 适用场景

- 提交前希望有人把代码过一遍，找出安全/正确性隐患
- 需要可勾选的修复清单，分批、可控地落地修改
- 不想让审查工具随意在源码里加「修改说明」类注释
